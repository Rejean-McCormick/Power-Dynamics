# Recognition, Coordination, and Value Routing

Power Dynamics originally emphasized a downstream question:

> **Who can capture value after it is created?**

Version 6.4 adds two upstream questions:

> **Who can make capacity or contribution socially recognizable?**
>
> **Who can connect that recognized capacity to the people, resources, timing, and situations in which it becomes actionable?**

This yields a fuller value chain:

```text
latent capacity
→ evidence
→ recognition
→ access
→ coordination
→ action
→ created value
→ distribution / capture
→ memory
→ future credibility
```

Power can arise at every conversion.

## 1. Recognition power

**Recognition power** is relational power arising from the ability to shape whether a capacity, contribution, claim, identity, qualification, or history becomes legible, trusted, certified, discoverable, admissible, or institutionally actionable.

Recognition power can be held by:

- employers;
- banks and credit systems;
- credentialing institutions;
- professional orders;
- platforms and ranking systems;
- reputation systems;
- brands;
- peers and communities;
- governments;
- technical registries;
- distributed evidence networks.

The mechanism is not inherently abusive. Recognition can reduce uncertainty and make cooperation possible among strangers.

The danger appears when:

```text
useful recognition
→ required recognition
→ single gatekeeper
→ constrained exit
→ standing / access dependency
```

At that point a recognition system can become a toll bridge.

## 2. Credibility as a reusable asset

Credibility can be modeled as an accumulated, contextual return from past evidence:

```text
contribution / performance
→ evidence
→ memory
→ credibility
→ lower trust / verification friction
→ opportunity
```

Credibility is therefore capable of compounding.

It can also be transferred or borrowed through mechanisms such as endorsements, guarantees, institutional affiliations, credentials, references, brand association, or co-signing. These mechanisms differ legally and socially, but they share a general function: one actor's recognized standing changes another actor's access or trust environment.

The core firewall is:

> **Credibility ≠ truth ≠ sovereignty ≠ general human worth.**

## 3. Credit and credibility

Financial credit is a specialized institutional conversion from expectations about future performance into present resource access.

A simplified representation is:

```text
credit access = f(credibility evidence,
                  income / cash flow,
                  collateral,
                  contractual enforceability,
                  liquidity,
                  institutional policy,
                  market conditions)
```

Credibility and credit therefore overlap but should not be collapsed.

A useful conceptual contrast is:

```text
credibility
= past / present evidence carried into future interaction

credit
= future expected performance converted into present purchasing / investment capacity
```

This makes memory central to both systems: reputational memory supports credibility; ledgers, contracts, and repayment history support credit.

## 4. The recognition loop

For actor `i`, domain `d`, observer / system `s`, and time `t`:

```text
E_i,d,t  = evidence / memory
C_i,s,d,t = contextual credibility reading of E
A_i,s,t  = access / opportunity produced by the reading
Y_i,t+1  = resulting action / output
```

A generic loop is:

```text
E → C → A → Y → E'
```

This produces a positive capability loop when evidence is portable and opportunity remains open.

It can also produce cumulative advantage:

```text
recognized
→ more opportunity
→ more visible success
→ more evidence
→ more recognition
```

and its inverse:

```text
unrecognized
→ fewer opportunities
→ fewer chances to generate evidence
→ continued under-recognition
```

This is why recognition infrastructure is a first-class power surface.

## 5. Recognition wedge

A recognition system may under-recognize relevant evidence or over-recognize prestige, inherited standing, status, popularity, or self-reinforcing incumbency.

The **recognition wedge** should not be defined as "true worth minus score." Human worth and contextual access are not commensurable in that way.

For a bounded outcome `X`, define instead:

```text
W_recognition = X_calibrated-evidence - X_observed
```

Examples of `X` include:

- access to a role;
- discoverability for a task;
- funding eligibility;
- admission to a bounded opportunity;
- expected chance of being considered under explicit criteria.

The comparison requires a defensible calibration baseline and must preserve uncertainty.

## 6. Coordination power

Recognition does not by itself create action.

Useful capability can remain latent because of:

- search costs;
- timing;
- fragmented knowledge;
- missing context;
- trust uncertainty;
- confidentiality constraints;
- organizational boundaries;
- scheduling;
- geography;
- incompatible interfaces;
- inability to discover willingness.

**Coordination power** is the effective ability to connect needs, people, knowledge, resources, permissions, timing, and workflow so that latent capacity becomes usable collective puissance.

A general routing function can be represented as:

```text
match = f(need,
          capability,
          evidence,
          availability,
          willingness,
          context,
          confidentiality,
          reliability,
          constraints)
```

The output is not automatically a decision. It can be a ranked or filtered set of viable coordination pathways.

## 7. Coordination wedge

The **coordination wedge** is value that could be produced with resources and capabilities already present but is not produced because coordination friction prevents activation.

When output can be measured consistently:

```text
W_coord = Y*_same-resources, lower-friction - Y_observed
```

In bounded labor or expertise settings, an operational proxy may compare useful available capacity with useful activated capacity, provided both are expressed in the same unit.

This complements the extraction wedge:

```text
extraction wedge
= value created but disproportionately captured

coordination wedge
= value never created because useful capacity was not connected and activated
```

The two can coexist.

## 8. Power over, power to, and power with

Recognition and coordination clarify three modes already present in the ontology:

```text
power over
= ability to condition another actor's effective possibilities

power to
= effective ability to act

power with
= capability generated through coordination
```

A coordination infrastructure can therefore increase `power to` and `power with` while simultaneously creating new `power over` if it becomes the gatekeeper for recognition, routing, identity, or access.

That duality is central.

## 9. Value states

Power Dynamics should distinguish at least four value states:

```text
created value
recognized value
monetized / exchangeable value
captured / retained value
```

They are not equivalent.

A capability can be real but unrecognized. A recognized contribution can remain non-monetized. A monetized flow can be captured by an actor who did not create most of the underlying value. A system can create large capability gains in others while capturing little of that value itself.

For kOA this implies a plural value set rather than one scalar:

```text
V = {
  technical,
  epistemic,
  artistic,
  symbolic,
  network,
  credibility,
  institutional,
  commercial,
  capability-created-in-others
}
```

These dimensions overlap and must not be naively summed.

## 10. Capability created in others

A high-leverage system can create value by increasing other actors' effective possibility:

```text
ΔC = C_after - C_before
```

where `C` must be decomposed into measurable capabilities appropriate to the context, such as:

- time to find relevant expertise;
- percentage of useful knowledge recovered;
- independent tasks completed;
- error / rework reduction;
- time from need to viable team;
- successful handoff rate;
- reuse of prior artifacts;
- founder hours required per activation;
- third-party replication rate.

`ΔC` is therefore an impact family, not yet one universal metric.

## 11. Constitutional requirements for recognition systems

Recognition infrastructure becomes especially dangerous when it affects high-impact access such as finance, employment, public standing, education, health, or access to vulnerable people.

A non-dominating design should prefer:

- domain-bounded evidence;
- contextual readings rather than universal scores;
- provenance;
- inspectability;
- contestation and correction;
- time / decay where relevant;
- minimal disclosure;
- plural policies and distributions;
- human or legally accountable decision authority where required;
- preserved rights independent of general reputation;
- interoperability and evidence portability;
- credible exit.

The target is not perfect measurement of people.

It is lower coordination friction **without turning recognition into total social permissioning**.

## 12. kOA as an experimental case

kOA should remain an application case for this theory, not the proof of it.

The hypothesis is that Koali, EkoH, Kristal, Konnaxion, SmartVote, Orgo, AI, and federation mechanisms can lower some recognition and coordination frictions while preserving plural authority and exit.

The claim becomes stronger only through bounded pilots that show measurable changes in effective capability.

The key empirical question is:

> **Does a group using the architecture become measurably more capable without becoming more terminally dependent on the architecture or its founder?**
