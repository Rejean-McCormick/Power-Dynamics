# Power Conversion and Routing Map

The central constitutional problem can be expressed as a routing problem:

```text
RESOURCE / CAPABILITY
        ↓
LEGITIMATE FUNCTION
        ↓
NEW LEVERAGE
        ↓
┌─────────────────────┬─────────────────────────┐
│ governed conversion │ silent conversion       │
│                     │                         │
│ advice              │ sovereignty             │
│ funding             │ vote buying             │
│ attention           │ truth                   │
│ maintenance         │ political control       │
│ execution           │ mandate capture         │
│ local capability    │ user captivity          │
└─────────────────────┴─────────────────────────┘
        ↓
ROUTING / FIREWALL / COUNTERPOWER
```

## Main conversion firewalls

| Source | Allowed / useful destination | Automatic destination to resist | Mechanisms |
|---|---|---|---|
| Expertise | advice, interpretation, warning | political sovereignty | domain bounds, parallel readings, baseline preservation |
| Money | funding, procurement, infrastructure | more votes / standing | democratic allocation rules |
| Brand | attention, affiliation, commerce | truth / legitimacy | architecture-first references, brand ≠ protocol |
| Narrative | translation, mobilization, memory | unquestionable authority | ethical self-binding, criticism, self-mockery |
| Credibility | discovery, trust cues | final authority | contestable evidence, plural distributions |
| Technical administration | maintenance, implementation | political outcome control | scoped roles, audit, revocability |
| Execution | carrying out mandate | redefining mandate | explicit decision-to-work boundary |
| Infrastructure | capability, continuity | captivity | self-hosting, substitution, federation |
| Incumbency | demonstrated reliability | permanent dominance | branch mobility, lineage, recombination |

## Main routing destinations

### Toward users

- portability;
- local operation;
- usable evidence;
- exit;
- substitution;
- personal optionality.

### Toward communities

- shared knowledge;
- local semantic governance;
- democratic allocation;
- collective memory;
- community-run distributions.

### Toward protocols

- explicit contracts;
- schemas;
- testable behavior;
- interoperability;
- independent implementations.

### Toward branches

- lineage;
- variation;
- comparison;
- discoverability;
- support accumulation;
- replacement capacity.

### Away from terminal founder ownership

- documentation;
- distributed mastery;
- protocolization;
- independent operation;
- separation of persona, brand, protocol, and governance;
- succession and maintainer plurality.

## Routing quality

A mechanism is not genuinely power-sharing merely because the license says “open” or because export exists in theory.

Power sharing should be evaluated by **effective possibility**:

> Can another actor actually reproduce, operate, understand, contest, substitute, or evolve the function under real conditions?

This is the difference between formal openness and effective counterpower.
