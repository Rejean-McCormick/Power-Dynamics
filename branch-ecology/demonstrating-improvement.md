# Demonstrating Improvement

"Better" must be decomposed.

A branch can claim improvement in accuracy, autonomy, auditability, cost, inclusion, resilience, usability, domain fit, latency, privacy or some other explicit dimension. It should also identify trade-offs and the population or context for which the improvement matters.

Evidence can include comparative outcomes, reproducible tests, reasoned argument, user experience, failure reduction or institutional adoption. Support and popularity may matter for viability but should remain separate from proof of quality.

This allows improvement to accumulate without producing a single universal score that hides disagreements about values and context.
