# kOA Propagation Loop Catalog

This catalog is a map of **candidate and partially evidenced loops**, not a claim that all loops are already active at scale.

| Loop | Core sequence | Primary governor |
|---|---|---|
| Build | tools → faster building → better tools | test / architecture discipline |
| Knowledge | use → result → memory → better next cycle | provenance / plurality |
| Economic | public software → adoption → paid responsibility → revenue → common capability | money ≠ authority |
| Credibility | real result → evidence → credibility → access → more real tests | evidence-state discipline |
| Demonstration | sources → World → cinematic demo → examination → pilot → better World | simulation ≠ evidence |
| SmartVote | objects → evaluations → signal → discovery → utility → more objects | domain bounds / raw baseline |
| Kintsugi | integration → capability → adoption → integration demand | replaceability / sidecar boundaries |
| Replication | packaging → independent instance → operational learning → easier next instance | local autonomy / no mandatory center |
| Human capacity | training → operator → deployment → experience → better training | independent assessment |
| Multilingual | language support → community access → contribution → better language resources | conformance tiers |
| Narrative | architecture → cultural form → understanding → technical exploration → new evidence/story | narrative ≠ factual authority |
| Machine-readable review | structured docs → AI-assisted review → questions / critique → better docs | source / status discipline |
| Movement self-use | contributors → kOA workflow → results → better kOA → more capable contributors | counterpower / fork / founder decentering |
| Founder decentering | founder work → protocol / docs / tools → autonomous operators → lower founder bottleneck | opposition + independent reproduction |
| Federation | local value → independent instances → interoperable exchange → network value → more local adoption | optional federation / exit |
| Cross-branch subsidy | branch return → shared asset → another branch → new return | conversion firewalls |

## High-value couplings

### Economic × Build × Deployment

`managed service → revenue → tooling → lower operating cost → more managed service`

### Credibility × Demonstration × Institutional Access

`pilot → evidence → credibility → better-targeted demonstration → qualified institutional review → pilot`

### UCKK × Capsule × Founder Decentering

`training → operator → reproducible deployment → less founder labor → more deployments → training cases`

### Kintsugi × SmartVote × Kompendio

`more connected objects/systems → more objects to compare → better contextual discovery → more integration utility`

### SemantiK × Community × Knowledge

`language support → new contributors → new knowledge / validation → more multilingual value → stronger language support`

The next stage for Power Dynamics is not to add more loops indefinitely. It is to instrument these transitions and determine which couplings materially alter adoption, replication, and autonomy.
