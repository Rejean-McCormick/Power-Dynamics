# Propagation: Field Definition

## Compounding

> **A return from prior action increases later capability in the same actor, branch, or system.**

`A(t) → action → return → A(t+1)`

## Propagation

> **A return generated in one locus lowers the activation cost, raises the expected value, supplies resources, or improves the viability of capability elsewhere.**

`A → return → lower barrier / greater possibility for B → B`

## Coupled propagation

> **Two or more feedback loops exchange returns such that progress in one loop increases the closure probability or throughput of another.**

`A → B → C → A`

## Propagation asset

A **propagation asset** is a reusable return that can cross an actor, branch, domain, deployment, language, or institutional boundary.

Examples:

- code;
- protocol;
- deployment automation;
- evidence;
- credibility;
- documentation;
- money;
- trained operators;
- templates;
- integrations;
- language resources;
- brand recognition;
- source corpora;
- standards;
- institutional relationships.

## Activation barrier

An **activation barrier** is any requirement that must be crossed before a new actor can obtain useful capability.

Examples:

- inability to understand the system;
- lack of relevant local data;
- deployment complexity;
- lack of trust;
- language mismatch;
- lack of trained operators;
- perceived lock-in;
- insufficient economic resources;
- integration friction;
- founder dependence.

Propagation mechanisms matter when they reduce one or more of these barriers without merely relocating dependency to a new center.

## Healthy propagation

Healthy propagation satisfies two conditions simultaneously:

1. more actors become effectively capable;
2. terminal dependency does not grow faster than distributed capability.

A system can spread rapidly while becoming more centralized. That is diffusion, not necessarily empowering propagation.
