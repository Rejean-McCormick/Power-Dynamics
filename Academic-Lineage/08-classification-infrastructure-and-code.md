# Classification, Infrastructure, Code, and Hidden Governance

This lineage supports one of Power Dynamics' most important claims:

> **Power can be embedded in technical and semantic architecture before any formal political decision occurs.**

## Langdon Winner — artifacts can embody politics

Winner argues that technical artifacts and systems can embody or require particular distributions of power and authority.

**Correspondence:** technical design choices belong on the Power Surface; they are not merely neutral implementation details.

Reference: Langdon Winner, “Do Artifacts Have Politics?”, *Daedalus* 109(1), 1980. https://www.jstor.org/stable/20024652

## Lawrence Lessig — code regulates

Lessig's work on cyberspace argues that software and hardware architecture regulate behavior alongside law, norms, and markets.

**Correspondence:** permissions, defaults, data models, ranking, reader policies, trust roots, update mechanisms, and interoperability rules are governance mechanisms.

Reference: Lawrence Lessig, *Code and Other Laws of Cyberspace*, 1999; *Code: Version 2.0*, 2006. https://hls.harvard.edu/bibliography/code-and-other-laws-of-cyberspace-version-2-0/

## Bowker & Star — classification has consequences

Bowker and Star show that classification systems and standards organize worlds, distribute visibility, and can encode consequential social assumptions.

**Correspondence:** SemantiK, Kristal schemas, ontologies, category systems, admissibility criteria, and metadata are forms of **semantic / classificatory power**.

Reference: Geoffrey C. Bowker and Susan Leigh Star, *Sorting Things Out: Classification and Its Consequences*, MIT Press, 1999. https://doi.org/10.7551/mitpress/6352.001.0001

## Star & Ruhleder — infrastructure is relational and becomes visible on breakdown

Their infrastructure studies emphasize that infrastructure is not merely equipment; it is embedded in practices, communities, standards, learned conventions, and installed bases.

**Correspondence:** kOA's technical layer should be audited in relation to actual users and institutions, not only against internal architectural elegance.

Reference: Susan Leigh Star and Karen Ruhleder, “Steps Toward an Ecology of Infrastructure,” *Information Systems Research* 7(1), 1996. https://doi.org/10.1287/isre.7.1.111

## Hidden-sovereignty audit

A technically decentralized system may still concentrate power through:

- default schemas;
- canonical registries;
- ranking algorithms;
- update keys;
- API compatibility requirements;
- moderation queues;
- model prompts / AI system instructions;
- search and discovery;
- identity providers;
- documentation that defines the “normal” implementation.

This literature strongly supports treating those mechanisms as constitutional surfaces rather than implementation trivia.
