# Epistemic Rules for the Repository

1. Preserve source terminology when summarizing a source.
2. Label reconstructions and new concepts explicitly.
3. Do not silently convert legacy proposals into current principles.
4. Preserve disagreements among current documents.
5. Treat technical claims about current implementation as provisional unless supported by direct specifications or code.
6. Avoid treating analytical thesis drafts as canonical technical specifications.
7. Do not infer perfect measurement of competence, ethics, credibility, legitimacy, or truth from the presence of a scoring mechanism.
8. Use source IDs for provenance and technical evidence for implementation claims.


## Architect-confirmed design notes

`USER-CONFIRMED-DESIGN` may be used for a current design intention explicitly confirmed by the project architect in the working process but not yet supported by a canonical source document or technical specification.

Rules:

- do not present it as source-derived;
- identify missing technical evidence;
- replace or supplement it with canonical documentation when available;
- distinguish design intention from deployed implementation.
