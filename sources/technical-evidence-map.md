# Technical Evidence Map

The current 28-file corpus is strong on philosophy, architecture summaries and institutional proposals. A rigorous v3 power audit should add direct technical specifications for the exact loci where power is encoded.

## Highest-priority evidence to import

1. **Civilizational Coherence — power/capture chapters**: capture, lock-in, verification, contestation, substitution, exit.
2. **kOA Digital Ecosystem Layer Model / Layer 0**: separation of functions and mandate boundaries.
3. **Kristal authority registry, trust roots, reader policies, federation/versioning**: epistemic authority and branch lineage.
4. **EkoH ScoreConfiguration, ScoreHistory, visibility/access policies**: who defines credibility readings and how changes are audited.
5. **SmartVote lens registry, defaults, raw/weighted storage, version governance**: discoverability and advisory power.
6. **Orgo RBAC, routing, escalation, closure and override rules**: administrative and execution power.
7. **Konnaxion moderation, discovery, identity and ranking policies**: attention and agenda power.
8. **Capsule Manager signing, registry, update, rollback and deployment profiles**: infrastructural sovereignty and choke points.
9. **Koali distribution specification**: credibility portability, alternative distributions and interoperability.
10. **Brand / trademark governance and founder-control inventory**: domains, repos, release keys, registries, marks and current real-world control.

## Audit rule

A normative statement such as "EkoH is non-sovereign" is not sufficient technical evidence. The audit must identify the configuration, permission, key, role, registry, default or protocol boundary that makes the statement true in practice.
