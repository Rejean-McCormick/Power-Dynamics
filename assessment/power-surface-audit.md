# Power Surface Audit

Use this audit to answer:

> **What kinds of power does this system generate, where can they convert, and where are they routed?**

## 1. Domain inventory

For each domain, record:

| Domain | Resources | Capacity | Puissance | Relational power | Main controllers |

| Political | | | | | |
| Economic | | | | | |

| Semantic | | | | | |
| Information / attention | | | | | |
| Credibility | | | | | |

| Administrative | | | | | |
| Technical / infrastructure | | | | | |
| Narrative / brand | | | | | |
| Cognitive / AI | | | | | |
| Mnemonic / temporal | | | | | |
| Evolutionary / counterpower | | | | | |

## 2. Conversion inventory

For every major conversion:

```text
source domain
→ mechanism
→ destination domain
→ resulting leverage
```

Record whether the conversion is:

- explicit or hidden;
- intended or emergent;
- reversible or sticky;
- scoped or cross-mandate;
- contestable or terminal.

## 3. Stacking test

Which actor or node controls multiple high-leverage surfaces?

Look especially for combinations of:

- identity;
- credibility;
- discoverability;
- allocation;
- workflow;
- infrastructure;
- signing / updates;
- brand / certification;
- monetary rails.

## 4. Routing test

For each major capability, identify who receives:

- **capability**;
- **authority**;
- **returns**;
- **optionality**.

## 5. Counterpower test

Can affected actors effectively:

- verify?
- contest?
- substitute?
- exit?
- self-host?
- fork?
- preserve identity / history / evidence?
- gather support for an alternative?

## 6. Terminality test

Ask:

> If this controller fails, captures the function, changes policy arbitrarily, or disappears, can the ecosystem continue through another viable path?

If not, the surface may be **terminal power**.

## 7. Output

A complete audit should produce:

1. a domain map;
2. a conversion graph;
3. a stacking map;
4. a routing map;
5. a counterpower map;
6. a terminality assessment;
7. a list of technical evidence still required.
